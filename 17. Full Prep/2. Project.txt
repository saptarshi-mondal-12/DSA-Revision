Q. Tell me about your recent project. 

⭐1. Introduction - 

✦Project Description: 
So my recent project is an Android app I built called ChawalKart.

ChawalKart is a modern rice-delivery android application where users can browse, add, and buy different rice varieties online and get them delivered directly to their doorstep. 

✦Problem Statement:  
The problem I wanted to solve was the difficulty customers face while buying rice. They often need to carry heavy 25–30 kg bags, and it becomes even difficult when purchasing multiple bags. Customers also have to travel to different vendors or wholesale markets for better pricing or bulk orders, which is time-consuming, and physically tiring.

✦Solution: 
ChawalKart solves all these issues in a single Android app  where users can explore multiple rice categories online, add items to the cart, place orders easily. It offers wide range of rice varieties, better pricing, smooth cart management and have special discounts that local shops usually don’t provide.


⭐2. Role - 

In this project, I handled everything end-to-end — from designing the UI/UX to building the entire Android app.
During development, I followed the Incremental model and went through the complete software development lifecycle, like:
1. Requirement Gathering
2. Analysis
3. Designing
4. Coding
5. Testing


⭐3. Key Features - 

The app has several important features like :

1. I implemented secure login and signup using Firebase Authentication, including Google Sign-In for quick access.

2. Users can add items to the cart with real-time quantity updates, mark items as favourites to make repeat ordering faster.

3. The app supports offline caching, so users can still browse products even with low internet connection.

4. Users can also view their complete order history and current orders details and many more.


⭐4. Technologies Used :-

In this project, I used Android Studio as the primary IDE, with Kotlin as the programming language, and XML for the frontend UI design.

On the backend side, I used Firebase including Firebase Authentication for secure login and Sign-In. I used Cloud Firestore as the real-time database for storing all product and order data, and Cloud Storage for managing product images.

I also integrated Firebase Cloud Messaging service for push notifications, used Glide for fast image loading, and SharedPreferences for storing small local data.

Altogether, these tools helped me build a smooth, fast, and reliable app.


⭐ 5. Impact: 

In terms of impact, ChawalKart actually reduced the physical burden for customers, saved their time, and made buying rice much easier

The app has successfully delivered more than 20+ real orders so far, and we’ve received positive feedback for the smooth checkout and fast delivery experience. 

Overall, this project helped me gain hands-on experience in Android app development and building user-friendly mobile solutions.


⭐6. Future Feature :-  

Looking ahead, if I expand the ChawalKart in future, I would love to add online payment integration like UPI, wallets, and cards, live order tracking with Google Maps, multiple address support with delivery time slots, a referral and cashback system, and even a vendor dashboard for managing stock and pricing.

✅Q2. What are the challenges or difficulties you faced during project?

Ans: I faced multiple challenges during the development process. I still remember some specific issues that took time to figure out:

In the beginning, setting up Firebase properly and configuring Android Studio with the correct API levels and Java/Kotlin SDK versions was a bit confusing.

Then, while working on the cart feature, I noticed another challenge. One major challenge was keeping the cart quantity updated when navigating between activities. For example, if a user changed the item quantity in the CartActivity, it should immediately reflect on the previous screen as well. I handled this by using a shared ViewModel so the data stays updated between activities.

Maintaining a smooth user experience was also a bit challenging for me like loading rice images and product details from the Firestore database slowed the app at first. I solved this by using Glide for fast image loading and use efficient loading techniques to maintain performance.

Another practical issue I faced was during slow or unstable internet. Users sometimes double-tapped the “Place Order” button, and the same order got placed multiple times when the connection came back.
I fixed this by showing a toast like “internet connection is low,” disabling the button when there’s no internet, and enabling it again when the connection restores, and also keeping it disabled after the first click so that multiple orders don’t happen.

So these were some challenges I encountered, and they helped me understand real problems in Android development. These challenges also improved my skills in UI design, backend integration, debugging, and writing cleaner, more reliable code.

✅Q12. Tell me about a time you solved a difficult or tricky technical problem.

Ans: Yes, I remember a challenging situation while building my ChawalKart project.

One major challenge was keeping the cart quantity updated when navigating between activities. For example, if a user changed the item quantity in the CartActivity, it wasn’t reflecting immediately when the user navigated back to the previous screen.

Another challenge was data persistence. Suppose a user added items to the cart but didn’t place an order. After 1–2 days, when they reopened the app, the cart became empty because the data wasn't being saved permanently.

To solve both issues, I implemented a single shared data source using SharedPreferences.
This allowed me to Store the entire cart permanently, so even if the app was closed and reopened after several days, the cart data remained intact.

I also updated the UI by reading the latest cart data from SharedPreferences in onResume() of each activity. This ensured that any update made to the cart was reflected across all screens instantly, without manually refreshing or reloading.

So this was a challenging problem that initially felt difficult but after spending time on it, I was able to solved it completely.




✅Q13. Why did you choose SharedPreferences instead of ViewModel?

Ans: ViewModel is not designed for permanent data storage. It only holds data as long as the activity or process is alive. If the user closes the app, removes it from recent apps, or if the OS kills the process, all data inside the ViewModel is lost.
But SharedPreferences gives me persistent storage, so the cart remains saved even if: App is closed or App is restarted or process gets killed.
That’s why I used SharedPreferences inside CartManager for storing the cart permanently.

✴️ Cross Question 5: What was your Firestore schema?
Ans: My Firestore schema was actually quite simple and easy to manage. I separated everything into clear collections so I could fetch data fast.

For example, I had a Users collection where each userId stored the user details like name, email, phone, address, gender, etc.

Then I had a Rice Categories collection — each document represented one rice category with fields like category name, category image, ratings, and so on.

For the actual items, I used a Products collection where each productId had the product name, price, description, rating, discount, and image URL.

For the ordering system, I kept two separate collections:

Live Orders for current ongoing orders

Complete Orders for finished order history

Both stored fields like userId, orderId, items, quantity, total amount, order status, time etc.

And finally, I added a Feedback/Complaints collection where each userId stored the name, email, phone, and the feedback message.
